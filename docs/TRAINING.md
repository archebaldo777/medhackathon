# Обучение и дообучение модели

Модель обучается скриптом `scripts/train.py` на CPU примерно за минуту. GPU не нужен. Ниже — формат данных, команды и порядок развёртывания новой модели.

## 1. Подготовка окружения

Нужен Python 3.12 или 3.13:

```bash
python3.12 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
```

## 2. Формат входных данных

**Исследования.** Папка, в которой каждая подпапка первого уровня — одно исследование. Имя подпапки совпадает с идентификатором `study` в таблице разметки. Файлы DICOM (`*.dcm`) могут лежать на любой глубине внутри неё:

```text
dataset/for education/
├── Исследования/
│   ├── 2.25.10245777060263212829333021434108890537/
│   │   └── series_003_2_CR/…/CR000000.dcm
│   └── …
└── разметка.xlsx
```

**Таблица разметки** (`.xlsx`, форма организатора). Первая страница, две строки заголовка, данные — с третьей строки. Значение `1` — нарушение есть, `0` — нет; пустая ячейка — метки нет, и изображение для этой цели не используется.

| Колонка | Содержание |
|---|---|
| B | `study` — имя папки исследования |
| C | Позвоночник: некорректная укладка |
| D | Позвоночник: не выравнена ось |
| E | Позвоночник: посторонние предметы |
| F | Правое бедро: некорректная укладка / ротация |
| G | Правое бедро: некорректная область интереса |
| H | Левое бедро: некорректная укладка / ротация |
| I | Левое бедро: некорректная область интереса |
| J | Позвоночник: итоговый класс качества |
| K | Правое бедро: итоговый класс качества |
| L | Левое бедро: итоговый класс качества |

Метки заданы на уровне исследования и переносятся на все изображения соответствующей области и стороны. Область и сторона каждого изображения определяются автоматически.

## 3. Обучение

С путями по умолчанию (`dataset/for education/Исследования` и `dataset/for education/разметка.xlsx`):

```bash
make train
```

Полностью, со всеми параметрами:

```bash
.venv/bin/python scripts/train.py \
  --studies "dataset/for education/Исследования" \
  --labels "dataset/for education/разметка.xlsx" \
  --output models/dxa_quality_v4.joblib \
  --metrics reports/validation_metrics_v4.json \
  --folds 5 --seed 42
```

Что делает скрипт:

1. Читает DICOM в детерминированном порядке и для каждой цели считает свой дескриптор критерия ТЗ (`src/features.py`, `TARGET_BLOCKS`): угол оси, поля в миллиметрах, локальный контраст, контур бедра.
2. Оценивает семь голов 5-fold кросс-валидацией `StratifiedGroupKFold` по исследованию, так что кадры одного пациента не попадают одновременно в обучение и проверку. Для целей, где это даёт выигрыш, кадры одного исследования и стороны агрегируются (mean/max).
3. Выбирает порог каждой головы по out-of-fold F1 при специфичности не ниже 0,60 и переносит его на итоговую модель по доле срабатываний.
4. Обучает итоговые головы на всех данных и сохраняет модель и отчёт метрик с 95% доверительными интервалами (кластерный бутстреп по исследованиям).

Результат повторяется при тех же данных, `--seed` и версиях пакетов из `requirements.txt`.

## 4. Развёртывание новой модели

1. Проверьте метрики в `reports/validation_metrics_v4.json`.
2. Прогоните тесты: `make test`.
3. Пересоберите образ: `./scripts/build.sh`. Либо, без пересборки, подключите модель томом и переменной `DXA_MODEL_PATH` (см. `docs/DEPLOYMENT.md`).

Файл модели хранит размер признакового вектора каждой головы. Если после изменений в `src/features.py` модель не переобучить, сервис не запустится и сообщит об этом явной ошибкой, вместо того чтобы молча выдавать неверные предсказания.

## 5. Дообучение на новых данных

Модель — ансамбль scikit-learn, поэтому дообучение — это полное переобучение на объединённом наборе (около минуты). Добавьте новые исследования в папку и строки в таблицу разметки в том же формате и запустите `make train`. Для данных с другого аппарата проверьте калибровку размера пикселя (`src/constants.py`, если в DICOM нет `PixelSpacing`) и определение области (`src/dicom_io.py`).

## 6. Сопутствующие скрипты

| Скрипт | Назначение |
|---|---|
| `scripts/error_analysis.py` | Анализ ошибок по клиническим подгруппам (сколиоз, эндопротез, переходный позвонок, перелом) на тех же фолдах → `reports/error_analysis.json` |
| `scripts/benchmark.py` | Скорость, память и детерминизм инференса на `dataset/for tests` → `reports/inference_benchmark.json` (`make benchmark`) |

## 7. Направления развития

1. Получить эталонную разметку денситометра (межпозвонковые уровни, область интереса бедра) и покадровую разметку ключевых точек (Th12, гребни подвздошных костей, большой и малый вертел).
2. Добавить данные разных производителей и учреждений, в том числе боковые проекции позвоночника.
3. Зафиксировать внешнюю отложенную выборку до подбора гиперпараметров.
4. Перейти к многозадачной нейросети (классификация, ключевые точки, сегментация).
5. Калибровать вероятности на отдельной выборке.
6. Провести reader study и клиническую валидацию до пилотной эксплуатации.

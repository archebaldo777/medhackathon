# Эвектио — полная документация

Сервис искусственного интеллекта для оценки качества денситометрических исследований (DXA). Решение команды **Эвектио** для задачи Центра диагностики и телемедицины, «Лидеры цифровой трансформации 2026».

Этот документ описывает решение целиком: от установки до устройства алгоритма. Короткие тематические руководства лежат рядом: [`USER_GUIDE.md`](USER_GUIDE.md) — пользователю, [`DEPLOYMENT.md`](DEPLOYMENT.md) — администратору, [`API.md`](API.md) — интегратору, [`TRAINING.md`](TRAINING.md) — для обучения модели, [`MODEL_CARD.md`](MODEL_CARD.md) — карточка модели.

> Исследовательский прототип поддержки принятия решений. Не является медицинским изделием и не заменяет проверку врачом.

## 1. Задача и решение

Достоверность денситометрии зависит не только от аппарата, но и от укладки пациента, выбора области, отсутствия артефактов и правильной разметки областей измерения. Контроль качества обычно выполняет специалист вручную. Эвектио автоматизирует этот первичный контроль: для каждого DICOM-изображения сервис

- определяет анатомическую область (поясничный отдел позвоночника, правое или левое бедро) и проекцию;
- решает, пригодно ли изображение для клинической интерпретации (`0` — качественное, `1` — есть нарушение);
- называет тип нарушения из закрытого списка организатора — одно или несколько;
- строит разметку областей измерения, как её рисует денситометр, и проверяет её по критериям ТЗ в миллиметрах;
- объясняет вывод: тепловая карта, измеренный угол оси, поля кадра, рекомендации по повторной укладке;
- формирует отчёт: CSV/XLSX, JSON и стандартные DICOM-объекты (SR, Presentation State, Secondary Capture);
- даёт специалисту подтвердить или отклонить вывод и исправить разметку.

Всё работает локально, в контейнере без сети; снимки никуда не передаются.

**Ключевая идея.** Критерии качества в ТЗ сформулированы в физических величинах: наклон оси не больше 5°, поля 3 см и 2 см, видимость конкретных анатомических ориентиров. Поэтому модель — не единый «чёрный ящик» над пикселями, а семь специализированных классификаторов («голов»). Каждый получает дескриптор, измеренный в градусах и миллиметрах именно для своего критерия. Это делает вывод объяснимым и устойчивым на небольшой выборке (100 исследований).

## 3. Архитектура

```text
                      ┌───────────────── вход ─────────────────┐
                      │ DICOM-файлы · папка · ZIP · список     │
                      └───────────────────┬────────────────────┘
                                          ▼
 batch.py        поиск DICOM (расширение или сигнатура DICM), безопасная распаковка ZIP
                                          ▼
 dicom_io.py     чтение pydicom · Rescale · MONOCHROME1 · цвет → оттенки серого
                 калибровка пикселя · нормализация по перцентилям
                                          ▼
 dicom_io.py     область: позвоночник / правое бедро / левое бедро
 projection.py   проекция: AP / LAT (теги DICOM)
                                          ▼
 analyzer.py     группировка кадров по (исследование, область)
                                          ▼
 features.py     дескрипторы критериев ТЗ: ось (°), поля (мм), артефакты, форма бедра
 model.py        7 голов → вероятности → пороги → класс, типы нарушений, quality_prob
                                          ▼
 markup.py       разметка L1–L4 / ROI бедра, шейка, квадрат Варда + проверки в мм
                                          ▼
 visualization   тепловая карта (окклюзия 8×8), ось, разметка → PNG
 dicom_sr        DICOM SR (серия 900) · dicom_viz Secondary Capture (901) · dicom_gsps GSPS (902)
                                          ▼
 reporting.py    results.csv · results.xlsx · manifest.json · result.zip
                                          ▼
 api.py / cli.py REST API и веб-интерфейс · командная строка
 review.py       подтверждение и коррекция разметки специалистом
```

| Модуль | Ответственность |
|---|---|
| `src/api.py` | FastAPI-приложение: пакетная обработка, задачи веб-интерфейса, выгрузки ZIP, подтверждение специалистом. Тяжёлая обработка выполняется в пуле потоков |
| `src/cli.py` | Команды `analyze` и `serve` |
| `src/batch.py` | Поиск файлов, распаковка ZIP (защита от Zip Slip, лимиты, кодировки имён), запись всех результатов |
| `src/analyzer.py` | Анализ изображений и групп, итоговая запись `AnalysisResult`, приоритет проверки, рекомендации |
| `src/dicom_io.py` | Чтение DICOM, калибровка, нормализация, определение области, распознавание DICOM-файлов |
| `src/projection.py` | Проекция и сторона по тегам |
| `src/features.py` | Признаки в физических единицах |
| `src/model.py` | Загрузка модели, проверка совместимости с кодом признаков, пороги, предсказание, тепловая карта |
| `src/markup.py` | Автоматическая разметка, проверки ТЗ, применение правок специалиста |
| `src/visualization.py` | PNG-визуализации |
| `src/dicom_sr.py`, `dicom_gsps.py`, `dicom_viz.py` | Производные DICOM-объекты |
| `src/review.py` | Решение специалиста: запись в SR, разметку и `manifest.json` |
| `src/reporting.py` | CSV, XLSX, JSON |
| `src/constants.py` | Области, нарушения, калибровка, колонки отчёта |
| `src/static/` | Веб-интерфейс (HTML/CSS/JS без фреймворков) |

Стек: Python 3.12, FastAPI, Uvicorn, pydicom, NumPy, SciPy, scikit-learn, Pillow, openpyxl.

## 4. Установка и запуск

### 4.1. Docker (основной способ)

Требуется Linux или macOS с Docker Engine 20.10+ / Docker Desktop.

```bash
git clone https://github.com/archebaldo777/medhackathon.git
cd medhackathon
./scripts/build.sh                                   # образ evectio:1.5.0
./scripts/analyze.sh "dataset/for tests" outputs/demo   # проверка на тестовом фрагменте
cat outputs/demo/results.csv
```

| Скрипт | Что делает |
|---|---|
| `scripts/build.sh` | `docker build` образа `evectio:1.5.0` (имя меняется переменной `DXA_IMAGE_NAME`) |
| `scripts/analyze.sh INPUT [OUTPUT]` | Пакетная обработка папки или ZIP в контейнере без сети; результаты в `OUTPUT` (по умолчанию `outputs/result`) |
| `scripts/run.sh` | API и веб-интерфейс на `http://localhost:8000` (порт — `DXA_PORT`); остановка — `Ctrl+C` |

Запуск в фоне с автоперезапуском, изолированный контур, обновление модели и типичные проблемы описаны в [`DEPLOYMENT.md`](DEPLOYMENT.md).

### 4.2. Без Docker

Требуется Python 3.12 или 3.13 (на macOS: `brew install python@3.12`).

```bash
python3.12 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/python -m src analyze "dataset/for tests" --output outputs/demo --zip
.venv/bin/python -m src serve            # или ./start_local.sh
```

### 4.3. Проверка установки

```bash
curl -f http://localhost:8000/health
# {"status":"ok","service":"evectio","version":"1.5.0","model_version":"dxa-quality-criteria-4.0"}
.venv/bin/pytest                         # 52 автотеста
```

## 5. Работа с сервисом

### 5.1. Веб-интерфейс

1. Откройте `http://localhost:8000`, нажмите «Загрузить исследование».
2. Перетащите DICOM-файлы или ZIP (или выберите кнопкой) и нажмите «Анализировать».
3. **Очередь просмотра** слева: сначала нарушения, затем сомнения (вероятность близка к порогу), затем норма. Отметка у строки — вердикт, справа — оценка риска.
4. **Карточка снимка**: вердикт и найденное нарушение, имя файла, область, проекция; три режима просмотра — «Снимок», «С ИИ» (тепловая карта, ось, разметка), «Разметка» (редактор); справа — риск, пояснение, измерения, проверки разметки, рекомендации по укладке.
5. **Подтверждение специалистом** под снимком: ФИО, комментарий, решение по разметке, кнопки «Подтвердить вывод» / «Отклонить вывод». После сохранения очередь переходит к следующему снимку.
6. Выгрузки: «Скачать ZIP» — одно исследование; «Все ZIP» — вся задача; «Отмеченные ZIP» — выбранные чекбоксами.

Навигация: стрелки `←`/`→`, клавиша `F` — во весь экран, `Esc` — выход. Результаты задачи хранятся на сервере 1 час. Подробно — [`USER_GUIDE.md`](USER_GUIDE.md).

### 5.2. Командная строка

```bash
python -m src analyze INPUT [--output OUT] [--zip] [--no-visualizations] [--model PATH]
python -m src serve [--host 0.0.0.0] [--port 8000]
```

`INPUT` — файл, папка (любая вложенность) или ZIP. Код завершения: `0` — все файлы обработаны; `2` — есть строки `Failure` (результат сформирован); `1` — ошибка входа или запуска. В stdout печатается JSON-сводка.

### 5.3. REST API

| Метод | Назначение |
|---|---|
| `POST /v1/analyze` | Пакет → ZIP с результатами; сводка в заголовке `X-DXA-Summary` |
| `POST /v1/jobs` | Пакет → JSON для интерфейса (задача хранится 1 час) |
| `GET /v1/jobs/{id}/download`, `/case/{i}/zip`, `/zip?indices=` | Выгрузки |
| `POST /v1/jobs/{id}/review/{i}` | Решение специалиста |
| `GET /health`, `GET /v1/model` | Состояние, метаданные модели |

Интерактивная схема — `GET /docs`, полный справочник с примерами — [`API.md`](API.md).

## 6. Входные данные

- **Формат:** DICOM, монохромные изображения `MONOCHROME1`/`MONOCHROME2` 8–16 бит. Цветные (RGB/YBR) переводятся в оттенки серого, у многокадровых берётся первый кадр.
- **Кодирование:** несжатый Little Endian (Explicit/Implicit VR), RLE, JPEG Baseline, JPEG 2000 — декодируются встроенными средствами `pydicom` и `Pillow`. JPEG-LS требует дополнительного декодера.
- **Распознавание файлов:** расширение `.dcm`/`.dicom`/`.dic`, сигнатура `DICM` на смещении 128 или — для файлов без расширения — корректный DICOM-заголовок без преамбулы. Пропускаются `DICOMDIR`, скрытые файлы, служебные папки `__MACOSX`.
- **Структура:** отдельные файлы, папка с любой вложенностью, ZIP (в том числе с кириллическими именами без UTF-8-флага: Windows, консольный `zip`), несколько ZIP.
- **Исследование:** до трёх изображений/серий. Кадры с одним `StudyInstanceUID` и одной областью/стороной анализируются как серия, потому что экспертная разметка задана на уровне исследования.
- **Используемые теги:** `StudyInstanceUID`, `SOPInstanceUID`, `PixelSpacing`/`ImagerPixelSpacing`/`NominalScannedPixelSpacing`, `RescaleSlope`/`Intercept`, `PhotometricInterpretation`, `ViewPosition`, `PatientOrientation`, `(Image)Laterality`, описания серии/протокола/исследования. Персональные данные не читаются и не нужны.
- **Лимиты API:** 1 ГБ на файл, 10 000 объектов и 5 ГБ в распакованном архиве.

## 7. Выходные данные

### 7.1. Таблица `results.csv` / `results.xlsx`

Одна строка — одно изображение. CSV — UTF-8 с BOM (корректно открывается в Excel), разделитель — запятая.

| Колонка | Формат | Значение |
|---|---|---|
| `path_to_study` | String | Путь относительно входной папки или корня ZIP |
| `study_uid` | String | `StudyInstanceUID`; при `Failure` берётся из заголовка файла; пусто, если тега нет |
| `image_uid` | String | `SOPInstanceUID`; при `Failure` берётся из заголовка файла; пусто, если тега нет |
| `anatomical_region` | String | `Поясничный отдел позвоночника` · `Проксимальный отдел бедра (правый)` · `Проксимальный отдел бедра (левый)`; `unknown` при `Failure` |
| `quality_class` | Integer | `0` / `1`; пусто при `Failure` |
| `violation_type` | String | Типы через `;`; пусто, если типы не сработали |
| `processing_status` | String | `Success` / `Failure` |
| `time_of_processing` | Float | Секунды на это изображение: чтение, доля анализа группы, результат и его файлы |
| `quality_prob` | Float | Оценка риска `[0; 1]`; `quality_class = 1` ⇔ `quality_prob ≥ 0,5` |
| `projection` | String | `Прямая (AP)` / `Боковая (LAT)` |
| `error` | String | Причина `Failure` или сообщение о несозданном SR, разметке, визуализации; пусто без ошибок |

`quality_class = 1` при пустом `violation_type` означает, что сработала только голова общего качества: изображение требует проверки, но ни один конкретный тип не превысил свой порог.

### 7.2. `manifest.json`

`summary` (`files`, `success`, `failure`, `with_violations`, `manual_review`) и массив `results`, по элементу на изображение:

| Поле | Содержание |
|---|---|
| колонки таблицы | Всё из раздела 7.1 |
| `projection_code`, `projection_source` | `AP`/`LAT` и источник: `dicom:ViewPosition`, `dicom:PatientOrientation`, `dicom:<описание>` или `protocol` |
| `laterality_source` | Источник стороны бедра: `image` или `dicom:Laterality` |
| `violations` | Для каждого типа: код, название, пояснение, вероятность и порог головы |
| `head_scores` | Вероятность и порог каждой головы области |
| `decision_threshold` | Единая рабочая точка `quality_prob` (0,5) |

## 8. Алгоритм

### 8.1. Предобработка

1. Декодирование `pydicom`, применение `RescaleSlope`/`RescaleIntercept`, инверсия `MONOCHROME1`, перевод цветных изображений в яркость (BT.601).
2. **Калибровка пикселя.** Берётся из `PixelSpacing` → `ImagerPixelSpacing` → `NominalScannedPixelSpacing`. В выгрузках организатора этих тегов нет, поэтому используется калибровка аппарата GE Lunar Prodigy Advance: 1,05 мм по Y и 0,60 мм по X. Пиксель анизотропен, поэтому все углы и расстояния считаются в миллиметрах: угол, измеренный в пикселях, был бы ошибочен примерно в 1,75 раза.
3. Нормализация яркости по 1-му и 99-му перцентилям в `[0; 1]`.

### 8.2. Анатомическая область и сторона

Поле сканирования позвоночника у аппарата стабильно шире (≈300 пикселей), чем у бедра (≈280), а костная масса позвоночника центрирована. У бедра диафиз смещён к одной стороне нижней половины кадра, и по положению центроида яркой костной массы определяется сторона. Если в DICOM заполнен `Laterality`/`ImageLaterality`, сторона берётся из тега. Для левого бедра изображение внутри модели зеркально приводится к ориентации правого, чтобы признаки формы были сопоставимы.

### 8.3. Проекция

По порядку: `ViewPosition` (`AP`/`PA` — прямая, `LL`/`RL`/`LATERAL` — боковая) → `PatientOrientation` (строки L/R и столбцы H/F — фронтальная плоскость, то есть прямая проекция; A/P и H/F — сагиттальная, боковая) → ключевые слова в описаниях серии, протокола и исследования. В данных организатора `PatientOrientation = L\F` — прямая проекция. Если ни одного тега нет, записывается стандартная для DXA прямая проекция с источником `protocol`. Модель обучена на прямых снимках, поэтому боковой снимок анализируется, но получает `review_priority = high`.

### 8.4. Признаки

Каждая голова получает свой набор дескрипторов (`src/features.py`, `TARGET_BLOCKS`):

| Блок | Что измеряет | Критерий ТЗ |
|---|---|---|
| `axis` | Трасса яркой колонны по строкам, наклон прямой в градусах, отклонение, наклон по третям, дрейф и ширина колонны | Ось позвоночника ≤ 5° (рис. 2) |
| `framing` | Поля от кости до краёв кадра в мм (сверху, снизу, слева, справа), размер костной области, профиль массы по высоте, физический размер поля | Th12 и гребни подвздошных костей (рис. 1); 3 см / 2 см вокруг ROI бедра (рис. 6) |
| `artifact` | Локальный контраст относительно сглаженной копии (top-hat), хвост ярких значений, яркость у краёв | Посторонние предметы, металл (рис. 3) |
| `hip_shape` | Медиальный контур бедра относительно собственного тренда, угол диафиза, ширины, грубая сетка 8×8 | Позиционирование и ротация по малому вертелу (рис. 4, 5) |

Каждый блок дополняется сводкой яркости и физическим размером поля.

| Голова | Блоки | Классификатор | Агрегация кадров |
|---|---|---|---|
| Позвоночник — общее качество | axis, framing, artifact | ExtraTrees | max |
| Позвоночник — укладка | framing | ExtraTrees | mean |
| Позвоночник — ось | axis | ExtraTrees | mean |
| Позвоночник — посторонние предметы | artifact | логистическая регрессия (C = 0,1) | mean |
| Бедро — общее качество | framing, hip_shape | ExtraTrees | max |
| Бедро — укладка/ротация | hip_shape | логистическая регрессия (C = 0,1) | max |
| Бедро — область интереса | framing | логистическая регрессия (C = 0,01) | max |

### 8.5. Решение

1. Каждая голова даёт вероятность. Порог головы выбран по out-of-fold F1 при специфичности не ниже 0,60 и перенесён на итоговую модель по совпадению доли срабатываний. Если перенос вырождается в край диапазона (0 или 1), используется сам out-of-fold порог.
2. **Типы нарушений** — головы типов, превысившие свои пороги.
3. **`quality_prob`** — максимум по головам области после монотонного пересчёта, при котором порог каждой головы переходит в 0,5. Поэтому `quality_class = 1` ровно тогда, когда `quality_prob ≥ 0,5`, и класс не противоречит вероятности.
4. **Приоритет проверки** — раздел 7.2.

### 8.6. Разметка областей измерения

В выгрузке организатора нет разметки денситометра: снимки 8-битные, без overlay и presentation state. Сервис строит её сам на изотропной сетке 1 мм:

- **позвоночник** — контур колонны, уровень гребней подвздошных костей, межпозвонковые линии T12/L1…L4/L5 (L4/L5 на уровне гребней, выше — по минимумам плотности с шагом тела позвонка), прямоугольники L1–L4 с общими боковыми границами;
- **бедро** — контур кости, большой вертел, головка (преобразование Хафа), окно шейки 15 мм поперёк шейки, квадрат Варда 10 мм, общая область интереса от головки до малого вертела с линией по диагонали.

Проверки по разметке в миллиметрах: «Над L1 видна половина тела Th12», «В поле видны верхние края подвздошных костей», «Поле выше / ниже области интереса ≥ 30 мм», «Поле от бокового края ≥ 20 мм». Дополнительно измеряется дуга оси позвоночника; дуга ≥ 6 мм помечается «вероятен сколиоз» (эксперты не считают сколиоз нарушением оси). Разметка объясняет вывод и редактируется специалистом, но не является входом модели.

### 8.7. Визуализация

Тепловая карта строится окклюзией: кадр делится на 8×8 участков, каждый по очереди заменяется медианой, и измеряется изменение вероятности головы. Так карта одинаково работает для деревьев и линейных моделей. Для позвоночника рисуются измеренная ось и эталонная вертикаль, поверх — разметка.

## 9. Подтверждение специалистом

Специалист принимает два решения:

1. **О выводе** — `confirmed` (согласен) или `rejected` (не согласен).
2. **О разметке** — `accepted` (верна), `edited` (исправлена перетаскиванием точек), `rejected` (неверна).

После сохранения:

- DICOM SR переписывается с `VerificationFlag = VERIFIED`, `VerifyingObserverSequence` и вердиктом;
- разметка (`dicom_markup`) переписывается с исправленными точками или удаляется при отклонении;
- `manifest.json` получает поле `review` (кто, когда, решение, исходный класс модели);
- архив задачи пересобирается.

`results.csv`/`results.xlsx` сохраняют вывод модели в формате ТЗ: решение специалиста не подменяет его.

## 12. Обработка ошибок

| Ситуация | Поведение |

## 13. Ограничения

- Одна модель аппарата (GE Lunar Prodigy Advance), 100 исследований, нет внешней валидации. Для других аппаратов нужна проверка калибровки пикселя, определения области и, вероятно, дообучение.
- Слабая разметка: метки даны на исследование, а не на снимок.
- Модель обучена на прямых проекциях; боковые снимки отправляются на ручную проверку.
- Если тегов проекции нет, проекция принимается стандартной (источник `protocol`).
- Автоматическая разметка эвристическая и не сверена с эталоном — его нет в данных.
- Известные слабые места: ложные срабатывания оси при сколиозе, пропуск эндопротеза как постороннего предмета.
- JPEG-LS требует дополнительного декодера `pydicom`.
- Производные DICOM сохраняют исходный `StudyInstanceUID` дословно, даже с ведущими нулями в компонентах (как в выгрузках организатора). Строгий PACS может выдать на такие UID предупреждение или отказ — совместимость проверяется на целевой системе.
- Сервис формирует DICOM GSPS, SR и Secondary Capture для импорта в совместимый PACS; сетевая отправка (C-STORE, STOW-RS), DICOM Conformance Statement и интеграционные тесты с PACS не входят в прототип.
- Публичный демо-стенд — только для обезличенных тестовых DICOM: файлы передаются на сервер стенда и удаляются автоматически не ранее чем через час, при очередном обращении к сервису. Принцип «данные не покидают контур» относится к локальному развёртыванию.
- Медицинское решение принимает специалист.

## 15. Безопасность и конфиденциальность

- Нет исходящих сетевых соединений; `analyze.sh` запускает контейнер с `--network none`.
- Персональные данные пациента не читаются. SR и DICOM-визуализация обезличены (пустые `PatientName`/`PatientID`).
- Временные файлы API удаляются после ответа; задачи веб-интерфейса — через час.
- Контейнер работает от непривилегированного пользователя.
- Встроенной аутентификации нет: для эксплуатации вне закрытого контура сервис ставится за reverse proxy с TLS и аутентификацией.

## 16. Глоссарий

| Термин | Значение |
|---|---|
| DXA | Двухэнергетическая рентгеновская абсорбциометрия (денситометрия) |
| ROI | Область интереса — зона измерения плотности |
| AP / LAT | Прямая (передне-задняя) / боковая проекция |
| Голова | Отдельный классификатор для одного критерия (класса качества или типа нарушения) |

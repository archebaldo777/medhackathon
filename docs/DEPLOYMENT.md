# Руководство по развёртыванию

## Требования

| | Минимум | Рекомендуется |
|---|---|---|
| ОС | Linux (x86_64 или arm64) или macOS | Linux-сервер |
| Docker | Docker Engine 20.10+ или Docker Desktop | — |
| CPU | 2 ядра | 4 ядра |
| RAM | 2 ГБ | 4 ГБ |
| Диск | 1 ГБ под образ + место под результаты | от 5 ГБ на SSD + место под результаты (≈ 0,9 МБ на снимок) |
| GPU | не нужен | не нужен |

Интернет нужен только при сборке образа: загружаются базовый образ `python:3.12.10-slim-bookworm` и пакеты из `requirements.txt`. Все версии зафиксированы. Готовый образ работает без сети.

## Сборка

```bash
./scripts/build.sh                 # образ evectio:1.5.0
```

Образ содержит только код (`src/`), модель (`models/`) и зависимости. Данные, тесты и документация в него не входят. Сервис внутри контейнера работает от непривилегированного пользователя.

## Пакетная обработка набора данных

```bash
./scripts/analyze.sh /data/test_dataset.zip /data/results      # ZIP
./scripts/analyze.sh /data/studies /data/results               # или папка
```

Скрипт:

- монтирует вход только на чтение;
- запускает контейнер с `--network none` — снимки физически не могут уйти в сеть;
- работает от имени текущего пользователя (`--user $(id -u):$(id -g)`), чтобы результаты в `/data/results` принадлежали вам;
- пишет `results.csv`, `results.xlsx`, `manifest.json`, дополнительные серии DICOM и `result.zip`.

То же вручную:

```bash
docker run --rm --network none --user "$(id -u):$(id -g)" \
  -v "$PWD/input:/input:ro" \
  -v "$PWD/output:/output" \
  evectio:1.5.0 \
  python -m src analyze /input --output /output --zip
```

Код завершения: `0` — все файлы обработаны, `2` — есть файлы со статусом `Failure` (результат всё равно сформирован), `1` — ошибка входа (например, не найдено ни одного DICOM).

## Запуск сервиса (API и веб-интерфейс)

```bash
./scripts/run.sh                   # http://localhost:8000
DXA_PORT=8080 ./scripts/run.sh     # другой порт
curl -f http://localhost:8000/health
```

Контейнер запускается в текущем терминале; остановка — `Ctrl+C` (контейнер удаляется автоматически). Чтобы сервис работал в фоне и перезапускался после перезагрузки сервера:

```bash
docker run -d --name evectio --restart unless-stopped -p 8000:8000 evectio:1.5.0
docker logs -f evectio             # журнал
docker stop evectio && docker rm evectio
```

`HEALTHCHECK` образа опрашивает `GET /health` каждые 30 секунд. Анализ выполняется в отдельном потоке, поэтому сервис отвечает на проверку и во время обработки большого пакета.

## Фиксация базового образа

Базовый образ в `Dockerfile` закреплён не только тегом, но и неизменяемым дайджестом:

```dockerfile
FROM python:3.12.10-slim-bookworm@sha256:fd95fa221297a88e1cf49c55ec1828edd7c5a428187e67b5d1805692d11588db
```

Поэтому сборка через год использует тот же базовый образ байт в байт, даже если тег в реестре перезапишут. Чтобы перейти на новую версию Python, узнайте её дайджест и замените строку:

```bash
docker pull python:<версия>-slim-bookworm
docker inspect --format '{{index .RepoDigests 0}}' python:<версия>-slim-bookworm
```

## Изолированный контур

Соберите образ на машине с интернетом и перенесите файлом:

```bash
docker save evectio:1.5.0 -o evectio-1.5.0.tar     # на машине сборки
docker load -i evectio-1.5.0.tar                   # на целевой машине
```

Для промышленной эксплуатации сервис ставится за reverse proxy с TLS, аутентификацией, лимитом размера запроса и журналом аудита без DICOM-тегов пациента: встроенной аутентификации нет. Временные файлы задач веб-интерфейса удаляются не ранее чем через час, при очередном обращении к сервису; публичный стенд без аутентификации допустим только для обезличенных тестовых DICOM.

## Обновление модели

После переобучения (`docs/TRAINING.md`) новая модель лежит в `models/dxa_quality_v4.joblib`. Пересоберите образ (`./scripts/build.sh`). Без пересборки путь к модели можно подменить переменной окружения и томом:

```bash
docker run --rm -p 8000:8000 -v "$PWD/models:/models:ro" \
  -e DXA_MODEL_PATH=/models/dxa_quality_v4.joblib evectio:1.5.0
```

## Ресурсы и масштабирование

Процесс сервиса занимает около 200 МБ памяти плюс около 0,5 МБ на каждое изображение обрабатываемого пакета: 2 ГБ хватает на пакеты примерно до 3 000 изображений. Изображение обрабатывается за 0,5–0,7 с вместе с PNG и DICOM-объектами (замер на 2 vCPU), так что исследование из 1–3 снимков укладывается в 1–2 с при лимите ТЗ 3 минуты. Результаты занимают около 0,9 МБ на изображение. Для параллельной обработки запустите несколько контейнеров за балансировщиком: каждый контейнер — один процесс с предсказуемым потреблением памяти.

## Наблюдаемость

- `GET /health` — готовность и версия модели;
- `GET /v1/model` — пороги, области, проекции, калибровка;
- HTTP `200` — пакет сформирован (внутри могут быть строки `Failure`); `4xx` — ошибка запроса или архива; `500` — контролируемая внутренняя ошибка в JSON;
- журнал запросов — стандартный вывод контейнера (`docker logs`).

## Типичные проблемы

| Симптом | Причина и решение |
|---|---|
| `permission denied: ./scripts/build.sh` | У скрипта нет флага исполнения (например, после скачивания ZIP вместо `git clone`): `chmod +x scripts/*.sh start_local.sh` или `sh scripts/build.sh` |
| `Cannot connect to the Docker daemon` | Docker не запущен: запустите Docker Desktop или `sudo systemctl start docker` |
| `permission denied while trying to connect to the Docker daemon socket` | Пользователь не в группе `docker`: `sudo usermod -aG docker $USER` и перелогиниться, либо запускать через `sudo` |
| `port is already allocated` / `address already in use` | Порт 8000 занят: `DXA_PORT=8080 ./scripts/run.sh` |
| `Unable to find image 'evectio:1.5.0'` | Образ не собран: сначала `./scripts/build.sh` |
| Результаты не записываются в папку вывода (`Permission denied`) | Контейнер запущен вручную без `--user`: используйте `scripts/analyze.sh` или добавьте `--user "$(id -u):$(id -g)"` |
| `DICOM-файлы не найдены` | Во входе нет DICOM: нужны файлы `.dcm`, `.dicom`, файлы с сигнатурой `DICM` или ZIP с ними |
| Строки `Failure` в `results.csv` | Отдельные файлы не читаются (повреждены или сжатый transfer syntax). Причина — в поле `error` в `manifest.json`; остальные файлы обработаны |
| При запуске без Docker `pip` не находит `scipy==1.18.1` или собирает `numpy` | Неподходящая версия Python: нужна 3.12 или 3.13 |

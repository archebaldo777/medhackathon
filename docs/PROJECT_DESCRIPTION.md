# Эвектио — ИИ-контроль качества DXA-исследований: описание проекта

Пояснительная записка команды **Эвектио** к задаче №4 хакатона «Лидеры цифровой трансформации 2026» — «Сервис искусственного интеллекта по оценке качества исследований плотности костей человека» (Центр диагностики и телемедицины).

## Задача

Специалист, принимающий денситометрическое исследование (DXA), должен вручную отсеять снимки с ошибками укладки, недостаточным полем ROI, наклоном оси или посторонними предметами — прежде чем измерение BMD станет клинически пригодным. Это рутинная, но критичная проверка: пропущенная ошибка укладки искажает результат так же, как ошибка самого измерения. Организатор поставил закрытый датасет из 100 исследований / 499 DICOM с экспертной разметкой нарушений и единый русскоязычный список из пяти типов нарушений.

## Решение

Эвектио — локальный сервис, который принимает DICOM (одним файлом, папкой или ZIP) и для каждого изображения возвращает: анатомическую область со стороной бедра и проекцию, бинарный класс качества (`0`/`1`), конкретный тип нарушения из закрытого словаря, объяснение (тепловая карта, измеренный угол оси, миллиметровые поля вокруг ROI) и рекомендацию по повторной укладке. Решение не отправляет снимки во внешние API — весь пайплайн, включая модель, работает в изолированном контейнере.

Ключевая идея — не единый чёрный ящик, а семь узкоспециализированных голов (по одной на класс качества и на каждый тип нарушения для двух анатомических областей), каждая из которых обучена на своём физическом дескрипторе: угол оси в градусах, поля кадра в миллиметрах, локальный контраст для посторонних предметов, отклонение контура бедра для ротации. Это отражение того, что сами критерии ТЗ сформулированы в физических единицах, а не как визуальное сходство.

## Что видит специалист

Веб-интерфейс показывает результат сразу после обработки, без обязательного скачивания. Очередь просмотра сортирует снимки: сначала нарушения, затем пограничные случаи, затем норма; один снимок отображается как слайд с переходом стрелками, кликом по строке очереди или клавиатурой, а сама область снимка и элементы управления всегда умещаются на экране без прокрутки страницы. Три режима просмотра — исходный снимок, наложение модели (тепловая карта, ось) и редактируемая разметка.

Разметка воспроизводит то, что обычно рисует денситометр при обработке (в предоставленной выгрузке её не было ни на одном снимке): контур кости и области измерения — межпозвонковые линии и прямоугольники L1–L4 для позвоночника, окно шейки и квадрат Варда для бедра. Специалист может скорректировать точки разметки вручную и затем подтвердить или отклонить вывод модели; решение переписывает статус DICOM SR на `VERIFIED` с именем специалиста и обновляет презентационное состояние разметки. После сохранения очередь автоматически переходит к следующему снимку. Результаты можно выгрузить как ZIP всей партии, ZIP одного исследования или ZIP отмеченных исследований.

## Архитектура и стек

FastAPI + Uvicorn, обработка DICOM через `pydicom`, признаки и модель — `numpy`/`scikit-learn` (L2-регуляризованная логистическая регрессия и ExtraTrees по головам), отчёты — `openpyxl`. Разметка и объяснения выгружаются как стандартные DICOM-объекты: Grayscale Softcopy Presentation State для разметки, Structured Report для статуса проверки, Secondary Capture для визуализации — все три открываются в обычном PACS-просмотрщике рядом с исходным исследованием. Интерфейс — одностраничное приложение без фреймворков. Контейнер собирается на `python:3.12-slim`, работает от непривилегированного пользователя, не требует GPU и не открывает сетевых подключений наружу.

Подробности: [`README.md`](../README.md) (полное описание пайплайна и формата результата), [`docs/API.md`](API.md) (все методы REST API), [`docs/DEPLOYMENT.md`](DEPLOYMENT.md) (сборка, офлайн-контур, ресурсы), [`docs/USER_GUIDE.md`](USER_GUIDE.md) (веб-интерфейс и CLI), [`docs/MODEL_CARD.md`](MODEL_CARD.md) и [`docs/TRAINING.md`](TRAINING.md) (модель и переобучение).

## Результаты валидации

Модель обучена на всех 100 исследованиях / 499 изображениях предоставленного набора, 5-fold `StratifiedGroupKFold` по идентификатору исследования (кадры одного исследования не разделяются между train и validation; идентификатор пациента в данных обезличен), seed 42. Out-of-fold метрики (полный отчёт — [`reports/validation_metrics_v4.json`](../reports/validation_metrics_v4.json)):

| Голова | F1 | ROC-AUC |
|---|---:|---:|
| Позвоночник — общее качество | 0,63 | 0,74 |
| Позвоночник — некорректная укладка | 0,62 | 0,85 |
| Позвоночник — ось не выравнена | 0,35 | 0,65 |
| Позвоночник — посторонние предметы | 0,58 | 0,79 |
| Бедро — общее качество | 0,54 | 0,67 |
| Бедро — некорректная укладка | 0,50 | 0,64 |
| Бедро — некорректная область интереса | 0,57 | 0,93 |

Macro-F1 по пяти типам нарушений — 0,53, средний ROC-AUC — 0,77. Чувствительность, специфичность и 95% доверительные интервалы — в README, раздел «Качество модели». Это exploratory-оценка на закрытых данных одного производителя аппарата (`Lunar Prodigy Advance`), не клиническая валидация.

## Ограничения

Обучающая выборка мала и получена на одном аппарате; внешняя многоцентровая валидация не проводилась. Разметка дана на уровне исследования, а не пикселя, и переносится на отдельные кадры — это слабая разметка. Автоматическая разметка эвристическая и не сверена с эталоном (его нет в данных): на снимках со сколиозом, эндопротезом или переходным позвонком L6 её нужно проверять особенно внимательно — это же указывает специалисту интерфейс. Модель обучена только на прямых проекциях: боковой снимок распознаётся по тегам DICOM и отправляется на обязательную ручную проверку. Полный список — в разделе «Известные ошибки, ограничения и их обработка» в [README](../README.md).

Решение — исследовательский прототип поддержки принятия решений. Он не является медицинским изделием и не заменяет проверку врачом; каждый результат требует подтверждения специалистом, для чего и существует экран подтверждения в интерфейсе.
